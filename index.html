ENVIROSOFT · CLAUDE PROJECT · JIRA / CONFLUENCE

Envirosoft Ticket Gap Analysis

A Claude Project that analyzes an Envirosoft Jira ticket, researches existing product behavior, identifies missing or contradictory requirements, and highlights related regression risks.

Claude ProjectsJiraConfluenceRequirements analysisRisk-based regression
Explore project details ＋

RESEARCH FIRST

Reviews ticket details, acceptance criteria, all comments, linked issues, attachments, screenshots, related Jira tickets, relevant Confluence pages, project knowledge, and applicable public sources. Findings are tied to their sources rather than answered from memory.

GAP CLASSIFICATION

Checks applicable scope, existing data, fields and validation, calculations, dates and time, workflow, access, downstream dependencies, environment, release constraints, and whether each acceptance criterion is verifiable. Classifies findings as Answered, Derived, Open Question, or Risk.

HIGH-VALUE QUESTIONS

Only asks questions that cannot be answered from sources or derived from requirements, that change implementation or expected behavior, and that require a person to decide. Questions include impact, a recommended answer, an owner, and a Blocking label when needed.

REGRESSION IMPACT

Identifies affected neighboring screens, shared components, reports, exports, APIs, integrations, downstream modules, existing records, client configurations, and historical defects. Prioritizes each area High, Medium, or Low with a measurable check.

STRUCTURED OUTPUT

Produces a plain-language summary, current-versus-new behavior, sourced requirements, open questions, issues and risks, prioritized regression areas, and links to sources. Jira comments and documentation suggestions are prepared only when requested.

SAFE BY DEFAULT

The Atlassian workflow is read-only by default. It does not edit, comment on, transition, or create Jira issues or Confluence pages unless explicitly asked. Unconfirmed information stays labeled, and missing evidence is stated rather than guessed.

CLAUDE · JIRA · EXCEL / CSV · QA DOCUMENTATION

Jira Ticket-to-Test Case Documentation

A questions-first QA workflow that clarifies a Jira ticket, builds a lean scenario list, and delivers structured Excel and CSV test cases for Envirosoft modules.

Requirements gapsTest scenarios7-column test casesExcelCSV
Explore project details ＋

QUESTIONS BEFORE SCENARIOS

Reads the ticket or supplied text/screenshots, summarizes what is understood, checks available module knowledge, asks numbered gap questions grouped by topic, and lists potential QA-impacting issues. It stops and waits rather than drafting scenarios prematurely.

READINESS GATE

Scenarios are generated after blocking questions are answered or explicitly skipped. Skipped items become recorded assumptions and are not silently treated as confirmed requirements.

LEAN SCENARIO DESIGN

Creates a two-column test scenario table with measurable outcomes, covers each acceptance criterion with positive and applicable negative checks, includes the original defect check for bug tickets, and merges related checks to reduce duplicate scenarios.

EXCEL AND CSV OUTPUT

Exports <TICKET>_Test_Cases.xlsx and .csv. The Test Cases sheet uses exactly seven columns: title, detailed description, precondition, main expected result, test step, test data, and expected result of each step. A Scenarios sheet retains the approved scenario list.

STEP-LEVEL QUALITY

Uses one row per test step, repeats the title for traceability, keeps description/precondition/main expected result on the first row only, groups navigation in step one, and requires a measurable expected result for every step.

TRACEABILITY & SAFETY

Jira remains read-only. The workflow avoids invented rules or production data, records assumptions and unresolved gaps, and ends with a Knowledge to save block for manually maintaining confirmed product knowledge.

from playwright.sync_api import Page, expect

def test_product_can_be_added_to_cart(page: Page, demo_url: str):
    page.goto(demo_url)
    page.get_by_role("button", name="Add to cart").click()
    expect(page.get_by_role("status").first).to_have_text(
        "1 item in your cart."
    )

def test_invalid_login_shows_validation_message(page: Page, demo_url: str):
    page.goto(demo_url)
    page.locator("#username").fill("wrong-user")
    page.locator("#password").fill("wrong-password")
    page.get_by_role("button", name="Sign in").click()
    expect(page.locator("#login-message")).to_have_text(
        "Invalid username or password."
    )
